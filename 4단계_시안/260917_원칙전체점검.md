# 원칙 전체 점검 (2026-09-17)

> **뒤이은 점검**: 시제품으로 옮긴 뒤 같은 원칙으로 다시 점검했다 — `시제품/260917_시제품_원칙점검.md` (E의 현재 상태도 거기에 있다).

4단계 시안 세 개(근로자 앱 W1~W9 · 지킴이 앱 G1~G8 · 공장주 웹 O1~O8 · 운영자 웹 M1~M5)를 원칙 4묶음의 **전체 항목**으로 훑은 결과다. 그때까지는 시안마다 대표 질문 몇 개만 봤다.

## 어떻게 했나

- 원칙 묶음마다 점검자를 따로 두고 동시에 훑었다. 점검자는 시안과 방법론 문서를 읽기만 했고, 이미 정한 결정은 뒤집지 않고 그 안에서 어긋나는 곳만 찾았다.
  - ① 닐슨 10원칙 — 모든 화면
  - ② ISA-101(화면) · ISA-18.2(경보) — 경보·현황 화면(W1~W4, W8-다, O1, O2, M1, M2-라·마)
  - ③ Microsoft 사람-AI 18원칙 — AI가 쓰이는 화면(체크리스트 AI 제안, 자동 번역, 센서 이상 판정, 고장 판단 보조)
  - ④ KWCAG 2.2 + 현장 조건 — 모든 화면. 흑백 스케치로 판단할 수 없는 항목은 "구현 때 확인"으로 따로 모았다.
- 만족한 곳은 적지 않고 △·✕만 적었다. 여러 묶음이 같은 곳을 짚은 것은 하나로 합치고 출처를 모두 적었다.
- 주요 지적은 시안을 다시 열어 사실인지 대조했다(예: O1-다에 고장 신고 버튼 없음, 지킴이 앱 요일이 2026년 달력과 다름 — 9/12·9/19는 토요일).
- 출처 표시: `닐`=닐슨 · `경`=ISA · `AI`=사람-AI · `접`=KWCAG·현장
- 크기: **크다** = 사용자가 할 일을 못 하거나 경보를 놓친다 / 작다 = 불편하지만 할 수 있다

## H. 구현 때 확인 (흑백 스케치로 판단할 수 없음)

- **대체 텍스트**: 상태 아이콘(⚠ · ? · 🔒 · ✓ · ☰ · 사진 · ›)에 글자 이름. ⚠와 ?(모름)는 화면 읽기에서도 다르게.
- **표의 구성**: 공장주·운영자 표의 머리칸 연결, 빈 머리칸("›" 열, "빼기" 열)에도 이름.
- **읽는 순서**: 좌우로 나뉜 화면(O1-다 등)도 결론 → 이상한 센서 → 일어난 일 순서로.
- **명도 대비 4.5:1**: 회색 작은 글씨(#555, #888), 흐리게 눌러 둔 칸, 입력 예시 글자. 햇빛 아래에서도.
- **자동 재생·정지**: 웹 현황판에서 경보 소리를 낸다면 끄는 수단. 진행 표시 움직임 멈추기.
- **깜빡임**: 경보에 번쩍이는 효과를 쓰면 초당 3회 미만.
- **키보드·초점**: 웹 대화상자(O1-마, O3-나)에서 초점이 창 안에 머물고 Esc로 닫힘. 표의 줄·누름표도 키보드로.
- **반복 영역 건너뛰기·제목**: 웹 위쪽 탭 건너뛰기, 페이지·대화상자마다 제목.
- **응답시간**: 인증번호 제한 시간 늘리기, 웹 자동 로그아웃 전 미리 알림.
- **포인터 입력 취소**: "조치 완료", "결과 내기"처럼 굳는 버튼은 손을 뗄 때 실행 — 장갑 낀 손이 미끄러지면 취소.
- **레이블과 네임**: 보이는 버튼 글자와 화면 읽기 이름을 같게(C1에서 "확인했어요"를 바꾸면 둘 다).
- **동작 기반 작동 금지**: 흔들기·기울이기 기능 두지 않기 — 진동이 심한 현장에서 저절로 작동.
- **기본 언어 표시**: 페이지 언어, W5-다의 한국어 병기, 외국인 이름, 번역문에 따로 언어 지정.
- **사용자 요구에 따른 실행**: 웹 자동 새로고침·새 창을 미리 알림.
- **레이블·오류 정정**: 인증번호·메모·의견 칸에 이름표, 빈칸·틀린 번호일 때 칸 옆 오류 문구.
- **접근 가능한 인증·반복 입력**: 인증번호 자동 채우기(`autocomplete="one-time-code"`)와 붙여넣기, 번호 미리 채우기.
- **마크업·앱 접근성**: 직접 만든 누름표·칩·켬/끔·체크 칸에 역할과 눌림 상태. 경보 도착·진행 상태는 화면 읽기에 바로 알림(aria-live). 네이티브 앱이면 TalkBack·VoiceOver로 시험.
- **글자 크게 설정**: 휴대폰 글자를 키워도 큰 버튼이 잘리지 않게 — 시안의 휴대폰 틀은 넘치면 잘리도록 그려져 있다.

## 해당 없음 (사람-AI)

G6 사회적 편향(사람을 판정하는 AI가 없고, 지킴이 평가 금지로 이미 막음) · G12 최근 상호작용 기억 · G13 사용자별 학습(이 서비스에 개인화가 없음. 운영자를 거쳐 AI를 고치는 흐름은 E17·E18·F4에서 봄).

## 원칙별 한 줄

- **① 닐슨**: 가장 많은 것은 일관성(예시 11건, 말·자리 7건). 가장 큰 것은 인터넷이 끊겨도 "이상 없음"(W1), 조치 완료를 못 보낸 상태가 없음(W2-나), 점검 답을 고칠 길이 없음(G5·G6), 다시 조치했어요가 없음(W2-다).
- **② ISA**: 평소 조용함·색 의존은 잘 지킴. 가장 약한 곳은 같은 상태의 말(e)과 억제된 센서의 가시성(k — M1에 수리 중 센서가 안 보임).
- **③ 사람-AI**: "틀릴 수 있어요" 표시는 잘 붙어 있음. 빈 곳은 AI가 멈췄을 때의 길(A1), 틀렸을 때 고치는 길(A2·A3·E17), 번역 읽음의 과신(B5), 익명 노출(B6).
- **④ KWCAG·현장**: 주 버튼(약 54px)과 홈 메뉴 칸(92px)은 장갑 기준을 넘음. 못 미치는 것은 보조 조작(작은 버튼 약 34px, 누름표·칩 30~37px, 언어 버튼 21~26px, 뒤로 가기, 5초 취소 약 30px)과 12px 이하 작은 글씨에 담긴 핵심 안내.
