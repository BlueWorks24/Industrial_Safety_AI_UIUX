# 시제품 — 폰에서 눌러 보는 시안

UI/UX 연구용 시제품이다. **진짜 서비스의 서버와 실제 데이터는 없다.** 작은 시제품 서버(`server.py`, 파이썬 기본 라이브러리만)가 화면 파일을 내주고, 임시 DB(`data/proto.db`, SQLite)에 시험용 계정과 가상 데이터를 둔다. 여러 기기(PC·폰)가 같은 데이터를 함께 본다. 공장·사람 이름은 모두 가상이고, 이야기는 "오늘 = 2026-09-17(목) 대성정밀"이다.

2026-09-17부터 **남은 화면 수정은 이 시제품에서 한다.** `4단계_시안/`의 HTML 스케치는 결정 기록으로 남긴다.

## 여는 법

```bash
./serve.sh            # 시제품 서버 + 임시 DB (기본 포트 8765)
./serve.sh --reset    # 임시 DB를 지우고 시험용 계정으로 다시 만든다
```

- PC: `http://localhost:8765/` · 휴대폰: 같은 와이파이에서 `serve.sh`가 알려 주는 주소
- 첫 화면에서 역할을 고른다: 근로자 · 안전지킴이 · 공장주·운영자. 아래 "⚙ 조작판"과 "처음 상태로"가 있다.
- 서버 없이(`python3 -m http.server`) 열면 브라우저 저장소로 돌아가고, 공장주·운영자 로그인은 안 된다(지킴이 앱은 김지킴으로 바로 들어간다).
- 네이버 지도는 등록한 주소에서만 뜬다 — PC에서는 **`http://localhost:8765/`로 열어야** 한다. 다른 포트·주소면 경계만 그린 그림 지도로 대신 보인다.
- 시험용 계정은 아래 "임시 DB와 로그인" 표 참고 (비밀번호 모두 `1234`).

### 다른 기계에서 시작할 때

필요한 것은 **파이썬 3뿐**이다. 설치할 꾸러미가 없다(`server.py`는 기본 라이브러리만 쓴다).

```bash
git clone https://github.com/BlueWorks24/Industrial_Safety_AI_UIUX.git
cd Industrial_Safety_AI_UIUX/시제품 && ./serve.sh
```

- `data/proto.db`는 따라오지 않는다(깃에서 뺐다). 처음 띄우면 시험용 계정과 씨앗 데이터로 다시 만들어진다.
- **윈도우에서는 `serve.sh`가 안 돌아간다**(bash 스크립트다). 대신 `cd 시제품` 뒤에 `python server.py --port 8765`. 폰에서 열 주소는 `ipconfig`의 IPv4 주소에 `:8765`를 붙이면 된다(같은 와이파이여야 하고, 처음엔 방화벽이 물어본다 — 허용).
- 화면 시험(`_시험/*.js`)까지 돌리려면 Playwright가 따로 필요하다: `npm i -g playwright && npx playwright install chromium`. 실행은 `NODE_PATH=$(npm root -g) node _시험/flow.js <캡처 폴더>`.
- 인터넷에 올릴 때는 저장소 뿌리의 `render.yaml`을 쓴다(Render 무료 등급, `python 시제품/server.py --port $PORT`).

### 지킴이 설문용 시험판 (2026-10-07)

지킴이분들께 드리는 주소는 개발용과 **따로** 둔다(`render.yaml`의 `industrial-safety-guard-survey`).
- **서버 없는 Render 정적 사이트**(무료, 잠들지 않음). 서버가 없으면 앱이 폰에 데이터를 둔다 — 지킴이마다 따로라 동시에 써도 안 섞인다. 대신 지킴이가 넣은 점검을 운영자 화면에서 모아 볼 수는 없다(사용자 결정).
- **첫 화면이 바로 지킴이 앱**(김지킴, 로그인 없음). 올릴 때 `시제품/`을 `dist/`에 복사하고 `guard.html`을 `index.html` 자리에 복사한다 — Render의 Root Directory·Publish Directory 칸이 한글을 안 받아서 영문 폴더로 옮긴다. Render 설정: Root Directory 비움 · Build Command `mkdir -p dist && cp -r 시제품/. dist/ && cp dist/guard.html dist/index.html` · Publish Directory `dist` · Branch `survey`. 이 판에서는 로그아웃 단추를 숨긴다(다시 들어올 길이 없어서), 비밀번호 바꾸기는 "시험판이라 바뀌지 않아요".
- **`survey` 가지만 따라간다** — main에서 고쳐도 설문 화면은 그대로. 설문판을 바꿀 때만 main을 survey에 합쳐 올린다.
- 네이버 지도는 NCP 콘솔에 새 주소를 더해야 뜬다(안 하면 그림 지도로 물러난다 — 쓰는 데는 지장 없음).
- 이야기 속 오늘은 그대로 9/17(목)이다. 폰의 브라우저 데이터를 지우면 처음 상태로 돌아간다.

## 지킴이 체크리스트 순서 (2026-09-18, 사용자 지시)

**기본 체크리스트가 먼저고 AI 제안은 원할 때 더하는 것이다.** 점검을 시작하면 사진 화면이 아니라 **업종별 기본 체크리스트**가 바로 나온다. 그 화면에서 "사진 찍어 AI 제안 받기"를 누를 때만 사진 → AI로 가고, 받은 제안은 같은 화면의 "AI 제안 · 원할 때만" 칸에 더해진다. 점검 도중에도 목록 화면의 "＋ 항목 더하기 · AI 제안 받기"로 다시 받을 수 있고, **이미 답한 항목의 답은 그대로 남는다.**

- 바뀐 것: 점검 시작 → `pick`(기본 체크리스트) · 사진·AI는 `pick`에서 들어가는 곁길 · `aiState`의 `skip`(AI 없이 시작)은 없어지고 `null`(안 받음)·`done`(받음)으로 갈린다 · "AI 없이 점검 시작" 버튼은 "기본 체크리스트로 돌아가기"가 되었다(받아 둔 제안과 고른 것은 지우지 않는다) · 이어서 점검할 때는 **안 본 첫 항목**으로 간다.
- 방법론 문서 흐름도도 같이 고쳤다(2026-09-18) — B② 점검 · B③ 사진 · B④ AI 추가 · B⑤ AI 항목 골라 더하기, B⑥~B⑨ 그대로. 나중에 다시 바뀔 수 있다.

**점검은 목록 한 장에서 줄마다 답한다 (2026-09-18 사용자 결정).** 한 항목을 화면 전체에 띄우고 하나씩 넘기던 방식(옛 `ans/n`)과 결과 보기(옛 `sum`)를 **한 화면(`list`)으로 합쳤다.** 지킴이는 같은 일을 반복하는 숙련 사용자라 전체를 보며 훑는 쪽이 빠르다. 넣은 것: 묶음 소제목(기본·AI·직접)과 항목 번호 · 머리글에 붙어 따라오는 진행 막대와 "n / 전체 답함" · "전체 / 안 본 것" 걸러 보기 · 답한 줄은 `✓ 이상 없음` / `⚠ 문제 있음 · 메모 · 사진` + "바꾸기" · 맨 아래 "문제로 찍은 항목" 모아 보기 · 다 답하면 "점검 결과 내기"(그 전에는 "안 본 항목 n개 보기"). "문제 있음"을 누르면 예전처럼 메모·사진 시트가 뜬다. 옛 주소 `#/ans/n`·`#/sum`은 `#/list`로 보낸다.

**답은 셋 · 버튼은 그대로 남는다 (2026-09-18 저녁, 해외 점검 앱 참고).** Procore Inspections와 GoAudits 안전 감사 서식을 보고 G5를 다시 손봤다.
- **`해당 없음` 추가** — 한 줄에 `이상 없음` / `문제 있음` / `해당 없음` 세 버튼(`.cans`). 그 공장에 없는 설비를 "이상 없음"으로 찍는 거짓 기록을 막는다. 빈칸이면 결과를 못 내므로 전에는 달리 길이 없었다.
- **답한 뒤에도 버튼이 남는다** — 고른 것만 색이 차고(`✓` 초록 / `⚠` 주황 / `—` 회색), 고칠 때 옆 버튼을 한 번만 누르면 된다. 옛 "바꾸기"(두 번 누르기)와 `.cst` 스타일은 없앴다. `문제 있음`을 다시 누르면 메모 시트가 다시 뜬다.
- **상태별 진행 줄과 수** — 머리글에 붙는 `.prog`가 초록·주황·회색으로 나뉘어 차고, 그 아래 `.tally`에 `✓ 이상 없음 n · ⚠ 문제 있음 n · — 해당 없음 n · 안 본 것 n`. (`.cnt`는 이미 다른 뜻으로 쓰이고 있어 `.tally`로 이름 붙였다.)
- **묶음 머리글을 눌러 접는다** — `기본 체크리스트 / AI 제안 / 직접 추가` 머리글이 버튼(`.grp.gh`)이 되어 접히고, `안 본 것 n` 또는 `다 답함`을 달고 있다. **저절로 접히지는 않는다** — 마지막 항목에 답하는 순간 손가락 밑에서 묶음이 사라지면 안 된다.
- **공장주 웹**(`owner.js` 점검 기록)도 `이상 없음 n개 · 해당 없음 m개`로 나눠 세고, 펼치면 `… — 해당 없음 (이 공장에 없는 것)`으로 구분해 적는다.
- **안 가져온 것**: 아래 탭 바 다섯 개 · `4.1 / 4.2` 두 자리 번호 · 오른쪽 위 작은 ⓘ · "구역 전체 해당 없음"(안전 점검에서 한꺼번에 넘기는 길은 두지 않는다).
- 동작: `data-act="ans"`(`data-v="ok|na"`) · `data-act="ansBad"`(시트) · `data-act="fold"`(`data-k=출처`). `ansOk`·`reAns`는 없앴다.

**화면 설명 줄을 걷어냈다 (2026-09-18 사용자 지시).** 지운 것: 홈의 "체크리스트 받아 둠" 배지 · 오늘 일정의 "가기 전에 볼 것 보기" · 내 할 일·점검 시작·내 점검 기록의 큰 제목 밑 설명 · 방문 전 "첫 점검이에요…" · 사진 화면의 단계 안내 · 항목 고르기의 "① → ② → ③" 안내와 AI 권유 설명 · 시트의 중복 설명 · 답한 항목 수 겹치는 줄. **남긴 것**(뜻이 있어서): "고르지 않아도 전부 점검" · "사진 속 것만 봐요 · 틀릴 수 있어요" · "사진에서 찾은 것 없음 — 위험이 없다는 뜻은 아니에요" · "전파 없음 / 전파가 잡히면 저절로 올라가요" · "내고 나면 고칠 수 없어요".

## 지킴이 앱을 기존 웹 방식에 맞춤 (2026-09-22)

- **재점검을 따로 두지 않는다 (2026-09-22 사용자 결정)** — 설계 때 정한 대로, 문제가 나오면 따로 재점검하러 가는 게 아니라 **나중에 그 공장을 다시 점검할 때 지난번 미흡이 반영됐는지 같이 본다.**

  - 문항 박스 왼쪽 색 띠를 없애고, 테마마다 흰 칸 하나에 줄로 묶었다(낸 점검 다시 보기와 같은 모양). 답 셋은 회색 틀 안에 나란히 두고 고른 것만 색으로 칠한다. 순서는 **해당 없음 | 문제 있음 | 이상 없음**.
  - **테마마다 한 쪽**: 지난번 미흡 → 01~05 → AI 제안 → 직접 추가 → **마무리**. 위 칩 줄로 쪽을 옮기고(칩마다 안 본 수, 다 보면 체크) 아래 `이전 | 다음: 테마 이름`으로 넘긴다. 마무리 쪽에 문제 항목, 점검 결과, 내기가 있다. 안 본 것이 남으면 내기는 잠기고 누르면 까닭을 알린다. `전체 / 안 본 것` 거르기와 테마 접기는 뺐다.
  - 답을 누를 때 칩 줄이 맨 왼쪽으로 튀던 것, "다음: 05 유해위험기 / 구/시설"로 꺾이던 것을 고쳤다(`유해위험 / 기구/시설`).
- **낸 뒤 화면**: 머리글을 달고 가운데로 모았다(AI 기다리기와 같은 배치). 초록 원이 튀어나오고 체크가 그려지는 움직임은 막 냈을 때 한 번만.
- **지도(하단바)**
  - 화성시 바깥 테두리 안을 **구 4곳**(만세구·효행구·병점구·동탄구)으로 나눠 구획도 색을 옅게 칠한다. 구 경계와 시 경계는 `geo.js`의 읍·면·동을 합쳐 미리 계산해 두었다(`HWASEONG_GU`).

  - **공장 핀**: 우리 조 공장 전부. 점검 예정(아래 공장 줄의 `점검 예정` 꼬리표와 같은 기준 — 할 일에 올랐거나 방문일이 잡힌 곳)은 파란 핀과 이름, 나머지는 작은 회색 점. 누르면 아래에 공장 줄.
  - 구를 골랐다 전체로 돌아오면 테두리가 사라지던 것을 고쳤다(네이버 지도 스타일에 빠진 값이 앞의 것으로 남았다 — 이제 모든 값을 늘 적는다).
- **공장 창의 ←**는 들어온 목록(홈·지도·캘린더·공장 전체보기)으로 돌아간다. 전에는 늘 홈으로 갔다.
- **홈 오늘 할 일**: 방문 시각은 색 칸 없이 굵은 숫자와 `방문`. 오늘 방문하는 공장마다 **AI 한 줄 요약**(지난번 미흡·센서 이상·지난 점검으로 짓는다, 가설). 요약 칸을 누르면 **요약 창**(요약 → 먼저 볼 것 → 근거 세 줄 → 공장 보기).

- **세로 고정**: 근로자·지킴이 앱은 세로로만. 안드로이드 홈 화면 앱은 방향을 잠그고(`manifest` `orientation`), 잠글 수 없는 곳(아이폰 사파리)은 가로로 돌리면 "세로로 돌려 주세요" 가림막.

## 지킴이 주간 보고 — 기존 웹 양식대로 (2026-10-01)

- 오전: 사용자 "정보가 한눈에 안 들어온다" → 요약 + 점검한 곳 목록 + 특이 사항으로 줄였다. 사용자가 그래도 애매하다고 해서 기존 웹 주간점검 등록 양식을 캡처로 확인했다(`../260921_기존시스템_분석.md` 8절).
- 오후: **기존 양식의 칸 그대로** 다시 그렸다(사용자 승인).
  - 기본 정보: 점검조 · 권역(고르기) · 기간 · 기업수
  - 점검한 기업: 결과별 수(점검완료 · 재점검 · 패트롤 · 기타) + 기업마다 한 칸(기업명 · 결과 · 점검일 · 업종 · 사업자번호 · 점검번호 · 비고 입력)
  - 중점점검항목: 줄마다 분야(점검 영역 고르기) · 항목 · 내용 · 비고, 더하기 · 지우기
  - 아래 단추 `○○ 주간 보고 내기`
- 기존 웹은 전부 손으로 적지만, 우리는 점검 기록에서 채운다. **지킴이가 적는 것은 기업별 비고와 중점점검항목뿐**이다.
- `가설`: 권역마다 따로 낸다(기존 양식이 권역을 하나만 고른다). 기업수 = 목록의 기업 수. 점검번호는 기존 점검코드 꼴(`R` + 날짜 6자리 + 차례 3자리)을 흉내 낸 임시 번호(가운데 글자 두 개는 뜻을 몰라 뺐다). 중점점검항목이 이번 주 것인지 다음 주 계획인지 모른다.
- 뺀 것: 지난주 대비 · 요일별 막대 · 찾은 문제 수와 테마별 문제 · 처리 상태 · 앞으로 예정 · 특이 사항 단추(점검 거부 등 — 이제 기업별 비고에 적는다). 모두 기존 양식에 없다.
- 홈 단추는 이번 주 점검한 곳이 있는 권역을 다 내야 `주간 보고 냄`이 된다.
- 시험 점검 3건을 더했다(새한테크 9/14 · 성원금속 9/15 재점검·검사 대기 · 한결화성 9/16 기타) → 이번 주 6곳, 권역 넷에 다 있다. 켜 둔 서버는 `처음 상태로`를 눌러야 보인다.

- **주간 보고는 업무 방식을 파악한 뒤 다시 만든다** (같은 날 사용자 결정). 기존 양식에 권역이 하나뿐인데 실제 조는 읍·면·동을 13곳 넘게 맡기도 해서, 권역마다 따로 내는 지금 가설은 틀렸을 수 있다(조마다 한 번일 가능성이 크다). 진흥원에 물을 것: 조마다인지 권역마다인지, 누가·언제 쓰는지, 중점점검항목이 이번 주 것인지 다음 주 계획인지, 실제로는 다른 길(한글 파일 등)로 내는지.
- **홈 "최근 점검한 곳" 단추** (같은 날 사용자 지시 — 이 칸의 단추는 그 공장에 관한 것만): `주간 보고 쓰기` → **`전화 걸기`**(처음엔 `공장에 전화`, 같은 날 사용자가 바꿈. 기업 정보의 회사 전화로 바로 걸기). 옆은 그대로 `점검 결과 보기`. 주간 보고는 하단바로 들어간다. 최근 점검한 곳이 없으면 단추 줄을 그리지 않는다. 그래서 공장과 상관없는 "내 점검 기록"(전체) 화면은 이제 들어갈 길이 없다.

- **홈 공장 카드 사이 간격 10px** (같은 날 사용자 지시 — 카드가 붙어 보였다). 거리순·일정순 둘 다. 캘린더 목록은 원래 12px 떨어져 있고, 공장 전체보기 줄은 그대로 붙어 있다.

## 지킴이 점검 고치기 — 장비 고르기, 답 넷, 예약 폐지 (2026-10-07, 사용자 지시)

**1. AI 길을 하나 더 — 장비 골라 AI 체크리스트.** 기본 체크리스트 화면에 단추가 둘이 된다: **사진 찍어 AI 제안 받기**(그대로) · **장비 골라 AI 체크리스트 받기**(새 화면 `#/equip`, G4-나). 둘 다 받아도 되고, 점검 항목에 같이 들어간다.
- 같은 날 처음엔 사진 길을 걷고 장비로 바꿨는데, 사용자가 "사진은 유지하고 추가로"라는 뜻이었다고 해서 사진 화면 · AI 기다리기 · AI 제안 고르기를 그대로 되살렸다. 상태도 따로 둔다 — 사진은 `aiState · ai`, 장비는 `eqState · eqGen`(기다리기 화면 `#/eqai`).
- 장비 목록(`seed.js` `EQUIP`, 27개)을 다섯 묶음으로 — 운반과 인양 · 깎고 자르는 기계 · 성형, 분쇄, 혼합 · 압력과 열 · 그 밖의 설비. 여러 개 고른다.
- **나이 있는 지킴이도 쓰기 쉽게** (같은 날 사용자: 알약이 작고 가독성이 떨어진다) — 큰 제목 "점검할 장비를 골라 주세요", 묶음 제목 18px 옆에 `n개 고름`, 장비는 **두 칸 격자의 큰 단추**(17px, 높이 58px)에 왼쪽 동그라미가 비었나 찼나로 고른 것을 보인다. 직접 적은 장비는 한 줄씩 큰 칸에 `✕ 빼기` 단추. 입력 칸과 더하기 단추도 높이 56px.
- 사용자가 준 목록(기존 체크리스트 05 영역의 장비)에 **고소작업대 · 연삭기 · 공기압축기 · 보일러 · 국소배기장치**를 더했다 — 05 영역에 있고 사고가 잦은 것. 두 번 적힌 "밀링"은 하나로, "이동식 및 천장 크레인"은 둘로 나눴다.
- **"기타 장비"는 목록에 두지 않고 "목록에 없는 장비" 칸에 이름을 적는다**(엔터나 더하기). 목록에 있는 이름을 적으면 그 칸을 골라 준다. AI가 적은 말이 무엇인지 알아보고(시제품은 `guessEquip` 흉내 — 호이스트 → 천장 크레인 종류, 톱 → 둥근톱, 원심 · 건조 · 탱크 · 집진 · 절곡 · 드릴, 모르면 "일반 기계 (확실하지 않음)") 그에 맞는 항목을 짓는다.
- 받으면 기본 체크리스트 화면에 **"AI 장비 체크리스트 장비 n개 m문항"** 칸과 장비마다 접힌 칸(직접 적은 것은 `직접 적음`과 "AI가 알아본 것"). "장비 바꾸거나 더하기"로 다시 고를 수 있고, 이미 답한 항목의 답은 남는다.
- 점검 화면에서는 사진 AI 제안이 "AI 제안" 한 쪽, 장비 체크리스트는 **장비마다 한 쪽**(칩 줄에 `지게차`, `프레스` …).
- 저장은 둘 다 `src: 'ai'`, 장비 것에는 `eq`(장비 이름)를 붙인다 — 운영자 통계 "AI 제안 쓰임"이 같이 센다.
- **문항 글(장비별 체크리스트 · 직접 적은 장비의 항목)은 Claude가 쓴 설명용 예시다** — 기존 웹이나 공식 점검표에서 가져온 것이 아니다. 사용자 결정(같은 날): 지금은 UI/UX 단계라 **내용은 나중에 만든다**. 그때 출처(기존 웹 점검항목 · KOSHA 자율점검표 · `참고자료/industry_equipment`)를 정한다. 05 영역 20문항(설비별)과 겹치는 것도 그때 정리.

**2. 답은 넷 — 양호 | 보통 | 불량 | 해당 없음** (전에는 해당 없음 | 문제 있음 | 이상 없음). 사용자가 말한 차례대로 왼쪽부터 놓았다.
- 저장 값 `ok · mid · bad · na`. 옛 `ok`는 양호, `bad`는 불량으로 읽는다. 보통은 금색(`#8f6a00`), 표시는 CSS 동그라미 — 글꼴의 ○가 다른 글자보다 크게 그려졌다. 360px 폰에서 "— 해당 없음"이 잘려서, 고른 칸의 표시는 양호 ✓ · 불량 ⚠만 남겼다.
- **불량**은 예전처럼 창이 뜬다 — 사진 · **위험요인 고르기** · 위험요인 내용(옛 "메모") · 평가 내용.
- **위험요인 18가지** (같은 날 사용자가 준 목록, `seed.js` `RISKS`) — 떨어짐(추락) · 넘어짐 · 무너짐 · 부딪힘 · 떨어짐(낙하) · 끼임 · 절단 · 근골격계 위험 · 이상온도 노출 · 이상기압 노출 · 소음 노출 · 유해위험물질 노출 · 산소결핍/질식 · 화재 · 폭발 · 전류 접촉 · 환경오염 · 기타. 장비 고르기와 같은 큰 두 칸 단추로 **여러 개** 고른다(`가설` — 하나만인지 모른다), 안 골라도 저장된다. 고른 것은 줄 아래 주황 꼬리표로, 낸 점검 · 공장주 웹 · 운영자 제출 검사에도 나온다(`risks`). 창이 길어져 취소 | 저장 줄은 창 아래에 붙여 두었다. 고를 때 창을 다시 그리지 않고 누른 칸만 바꾼다(다시 그리면 창이 위로 튀고 올라오는 움직임이 다시 나왔다). 사진 찍기 · 사정 고르기로 창을 다시 그려도 적던 글이 남게 고쳤다. 지난번 미흡 항목은 `불량 = 아직 안 고쳐짐`, 양호와 보통은 고쳐짐으로 센다(`common.js` `FIXED_ANS`).
- **평가 내용** — 어느 답이든 줄 아래 "＋ 평가 내용"을 눌러 적는다(잘한 점 같은 것, 안 써도 됨). 적으면 그 글이 회색 칸으로 보이고 눌러 고친다. 낸 점검 다시 보기 · 공장주 웹 · 운영자 제출 검사에도 나온다.
- 공장주에게 개선 요청이 가는 것은 지금처럼 불량뿐. 지킴이 · 공장주 · 운영자 화면의 "문제 있음 / 문제 n개 / 메모"를 "불량 / 불량 n개 / 위험요인"으로 바꿨다.
- CSS `.mid`가 이미 제목 글씨라 답 "보통"의 클래스는 `amid`다(겹쳐서 집계 글씨가 커졌었다).

**3. 방문 예약을 걷었다.** 실제로는 예약 시스템이 없고, 공장주와 따로 날을 맞추거나 연락이 안 돼 불시에 가기도 한다(사용자가 진흥원에서 들은 것).
- **점검 시작은 늘 열려 있다** — 홈 공장 카드, 공장 창 모두. 하던 점검이 있으면 "이어서 점검".
- 방문일은 지킴이가 스스로 적는 것만 남았다 — "방문일 정하기 / 일정 변경" → 같은 달력 창 → **저장하면 바로 캘린더에**(공장주 승인 없음). 창에 "잡아 둔 방문일 지우기".
- 걷은 것: 공장주 웹 "지킴이 방문 예약 요청" 칸(승인 · 거절), 조작판 "공장주 방문 예약 승인", 운영자 방문 일정의 상태 · 요청한 지킴이 칸, 공장주 공지 "지킴이 방문 예약은 웹에서 승인해 주세요", `common.js`의 `bookOf · bookRequest · bookApprove · bookReject`. 켜 둔 서버 데이터에 남은 `s.books`는 아무도 읽지 않는다(`SEED.v`는 그대로).

**4. 공장 점검 상태(점검 필요 · 재점검 · 점검완료 · 패트롤 · 기타)** 이야기는 사용자가 "지금은 참고만" 하라고 해서 화면에 넣지 않았다. 회의록에 정리할 예정.

- **여러 기기가 같은 데이터를 본다.** 각 화면이 1초마다 서버에서 새 데이터를 받는다. 두 기기가 동시에 바꾸면 늦은 쪽이 최신을 받아 다시 적용한다.
- **근로자는 초대로 들어온다** (설계대로). 시험용 초대 코드 — `DS-KIM`(김근로·한국어) · `DS-NGUYEN`(Nguyen Van A·베트남어) · `DS-USED`(이미 쓴 초대) · `DS-OLD`(기간 지난 초대). 열린 초대는 여러 번 시험하도록 써도 닫지 않는다(시험 편의). 링크로 열기: `worker.html#/join/DS-KIM`. 앱과 웹은 로그인 쿠키를 따로 쓴다.
- **지킴이 앱 로그인 (2026-09-23)** — 아이디·비밀번호(사용자가 고름), 로그인 상태 유지는 켜진 채로 연다(켜면 30일, 끄면 브라우저를 닫을 때까지). 지킴이 계정은 웹에, 공장주·운영자 계정은 지킴이 앱에 못 들어간다. 근로자 앱·지킴이 앱·웹은 쿠키를 따로 쓴다(`asid`·`gsid`·`sid`). 서버 없이 열면 김지킴으로 바로 들어간다. 옛 `data/proto.db`는 서버를 다시 띄울 때 계정 표가 저절로 새 규칙으로 옮겨지고 지킴이 계정이 더해진다.
- **지킴이 내 정보 G1-나 (2026-09-23)** — 사용자가 고른 것: 소속(분야·조·조장·조원·담당 권역·담당 공장 수, 보기만) · 계정(아이디, 비밀번호 바꾸기 창) · 문의(운영센터 전화, 가상 번호) · 로그아웃(확인 창). 안 올라간 점검이 있으면 로그아웃 단추가 잠기고 누르면 까닭을 알린다. 받아 둔 자료 보기·지우기(9/15 시안 G1-나)는 이번에 넣지 않았다.
- **공장 사진 → 지도 (2026-09-23 사용자 결정)** — 공장마다 사진을 찍어 모으기는 일이 늘고 첫 단계에서 못 한다. 홈 카드·최근 점검한 곳·공장 전체보기는 `geo.js` 경계로 그린 작은 지도(공장이 있는 읍·면·동 + 점, 카드마다 네이버 지도를 부르면 느리고 사용량이 늘어서), 공장 창은 네이버 지도 한 벌(공장 자리 핀, 공장만 바꿔 다시 씀). 네이버 지도가 안 뜨면 공장 창도 그린 지도로 보인다.
- **지킴이 앱 다듬기 (2026-09-23 오후, 모두 사용자 지시)**
  - 점검 고르기: 기본 체크리스트 영역을 누르면 문항이 펼쳐진다(아코디언). "고르지 않아도 전부 점검해요" 줄과 AI 제안 옆 "원할 때만·아직 안 받음" 꼬리표를 뺐다. AI 받기 단추는 옅은 보라→파랑.
  - 공장 창: 탭 셋 **기업 정보(처음) | 점검 준비 | 기록**. 기업 정보는 기존 화성 웹 기업정보 항목(대표자·사업자번호·전화·팩스·메일·업종코드·주생산품·상시/외국인 근로자·소유 형태·기업 종류·주소)을 카드 넷으로, 값은 모두 가상(`seed.js` FIRM). 기록 탭은 센서 이상·점검 이력 전부.
  - 지도 전체화면: 공장 창 지도와 지도 탭 지도 왼쪽 위 단추 → 화면을 덮는 지도, 왼쪽 위 "닫기".
  - 공장 창 예약 단추가 안 열리던 것 고침(예약 창을 공장 창에 안 붙였었다). 화면이 바뀌면 열린 창·전체화면은 닫힌다.
  - 사진 찍기(G4): AI 머리 칸, 찍을 곳 알약, 3칸 사진판과 사진마다 지우기(번호는 유지), 0장이면 보내기 잠김.
  - AI 기다리기: 가운데 모음, 도는 빛 고리, 바뀌는 한 줄, 사진 훑는 빛줄기.
  - AI 제안: 4개 → 사진 장수에 따라 최대 10개, 모두 고르기, 사진 꼬리표 카드.
- 근로자 앱 화면 말은 `i18n.js`에 한국어·베트남어·영어로 있다. 베트남어·영어는 **초벌 번역이라 원어민 검수가 필요**하다. 경보 문구는 미리 번역한 문구, 공지·의견 본문만 "AI 번역" 표시가 붙는다.
- 공장주 의견 화면이 생겼으므로 조작판의 "최근 의견 · 대표님 읽음/답/해결함"은 빠른 시연용으로만 남겨 둔다.
- 공장주가 만든 초대는 한 번 쓰면 닫힌다. 새 공지·답의 외국어 번역은 "(AI 번역 시연 · 언어) 원문" 꼴의 가짜다 — 실제 번역은 붙이지 않았다.
- **아이디·비밀번호 로그인은 시험 편의로만 쓴다** (2026-09-17). 설계 결정은 그대로 "공장주는 휴대폰 번호 인증"이다.
- 이 시제품은 UI/UX 연구 도구다. 화면·흐름에 공을 들이고, 서버·DB·인증은 적당히 돌아갈 만큼만 만든다.
