# 시제품 — 폰에서 눌러 보는 시안

UI/UX 연구용 시제품이다. **서버와 실제 데이터는 없다.** 가상의 서버와 데이터가 있다고 치고, 브라우저 저장소 안에서 돌아간다. 이야기는 "오늘 = 2026-09-17(목) 대성정밀"이다.

2026-09-17부터 **남은 화면 수정은 이 시제품에서 한다.** `4단계_시안/`의 HTML 스케치는 결정 기록으로 남긴다.

## 여는 법

```bash
./serve.sh            # 시제품 서버 + 임시 DB (기본 포트 8765)
./serve.sh --reset    # 임시 DB를 지우고 시험용 계정으로 다시 만든다
```

- PC: `http://localhost:8765/` · 휴대폰: 같은 와이파이에서 `serve.sh`가 알려 주는 주소
- 첫 화면에서 역할을 고른다: 근로자 · 안전지킴이 · 공장주·운영자. 아래 "⚙ 조작판"과 "처음 상태로"가 있다.
- 서버 없이(`python3 -m http.server`) 열면 브라우저 저장소로 돌아가고, 공장주·운영자 로그인은 안 된다.

### 다른 기계에서 시작할 때

필요한 것은 **파이썬 3뿐**이다. 설치할 꾸러미가 없다(`server.py`는 기본 라이브러리만 쓴다).

```bash
git clone https://github.com/BlueWorks24/Industrial_Safety_AI_UIUX.git
cd Industrial_Safety_AI_UIUX/시제품 && ./serve.sh
```

- `data/proto.db`는 따라오지 않는다(깃에서 뺐다). 처음 띄우면 시험용 계정과 씨앗 데이터로 다시 만들어진다.
- **윈도우에서는 `serve.sh`가 안 돌아간다**(bash 스크립트다). 대신 `cd 시제품` 뒤에 `python server.py --port 8765`. 폰에서 열 주소는 `ipconfig`의 IPv4 주소에 `:8765`를 붙이면 된다(같은 와이파이여야 하고, 처음엔 방화벽이 물어본다 — 허용).
- 화면 시험(`_시험/*.js`)까지 돌리려면 Playwright가 따로 필요하다: `npm i -g playwright && npx playwright install chromium`. 실행은 `NODE_PATH=$(npm root -g) node _시험/flow.js <캡처 폴더>`.
- 인터넷에 올릴 때는 저장소 뿌리의 `render.yaml`을 쓴다(Render 무료 등급, `python 시제품/server.py --port $PORT`).

  - 한빛화학: 1번 교반기 · 가스 · 전기 · 누수 · 온습도

## 지킴이 체크리스트 순서 (2026-09-18, 사용자 지시)

**기본 체크리스트가 먼저고 AI 제안은 원할 때 더하는 것이다.** 점검을 시작하면 사진 화면이 아니라 **업종별 기본 체크리스트**가 바로 나온다. 그 화면에서 "사진 찍어 AI 제안 받기"를 누를 때만 사진 → AI로 가고, 받은 제안은 같은 화면의 "AI 제안 · 원할 때만" 칸에 더해진다. 점검 도중에도 목록 화면의 "＋ 항목 더하기 · AI 제안 받기"로 다시 받을 수 있고, **이미 답한 항목의 답은 그대로 남는다.**

- 바뀐 것: 점검 시작 → `pick`(기본 체크리스트) · 사진·AI는 `pick`에서 들어가는 곁길 · `aiState`의 `skip`(AI 없이 시작)은 없어지고 `null`(안 받음)·`done`(받음)으로 갈린다 · "AI 없이 점검 시작" 버튼은 "기본 체크리스트로 돌아가기"가 되었다(받아 둔 제안과 고른 것은 지우지 않는다) · 이어서 점검할 때는 **안 본 첫 항목**으로 간다.
- 방법론 문서 흐름도도 같이 고쳤다(2026-09-18) — B② 점검 · B③ 사진 · B④ AI 추가 · B⑤ AI 항목 골라 더하기, B⑥~B⑨ 그대로. 나중에 다시 바뀔 수 있다.

**점검은 목록 한 장에서 줄마다 답한다 (2026-09-18 사용자 결정).** 한 항목을 화면 전체에 띄우고 하나씩 넘기던 방식(옛 `ans/n`)과 결과 보기(옛 `sum`)를 **한 화면(`list`)으로 합쳤다.** 지킴이는 같은 일을 반복하는 숙련 사용자라 전체를 보며 훑는 쪽이 빠르다. 넣은 것: 묶음 소제목(기본·AI·직접)과 항목 번호 · 머리글에 붙어 따라오는 진행 막대와 "n / 전체 답함" · "전체 / 안 본 것" 걸러 보기 · 답한 줄은 `✓ 이상 없음` / `⚠ 문제 있음 · 메모 · 사진` + "바꾸기" · 맨 아래 "문제로 찍은 항목" 모아 보기 · 다 답하면 "점검 결과 내기"(그 전에는 "안 본 항목 n개 보기"). "문제 있음"을 누르면 예전처럼 메모·사진 시트가 뜬다. 옛 주소 `#/ans/n`·`#/sum`은 `#/list`로 보낸다.

**답은 셋 · 버튼은 그대로 남는다 (2026-09-18 저녁, 해외 점검 앱 참고).** Procore Inspections와 GoAudits 안전 감사 서식을 보고 G5를 다시 손봤다.
- **`해당 없음` 추가** — 한 줄에 `이상 없음` / `문제 있음` / `해당 없음` 세 버튼(`.cans`). 그 공장에 없는 설비를 "이상 없음"으로 찍는 거짓 기록을 막는다. 빈칸이면 결과를 못 내므로 전에는 달리 길이 없었다.
- **답한 뒤에도 버튼이 남는다** — 고른 것만 색이 차고(`✓` 초록 / `⚠` 주황 / `—` 회색), 고칠 때 옆 버튼을 한 번만 누르면 된다. 옛 "바꾸기"(두 번 누르기)와 `.cst` 스타일은 없앴다. `문제 있음`을 다시 누르면 메모 시트가 다시 뜬다.
- **상태별 진행 줄과 수** — 머리글에 붙는 `.prog`가 초록·주황·회색으로 나뉘어 차고, 그 아래 `.tally`에 `✓ 이상 없음 n · ⚠ 문제 있음 n · — 해당 없음 n · 안 본 것 n`. (`.cnt`는 이미 다른 뜻으로 쓰이고 있어 `.tally`로 이름 붙였다.)
- **묶음 머리글을 눌러 접는다** — `기본 체크리스트 / AI 제안 / 직접 추가` 머리글이 버튼(`.grp.gh`)이 되어 접히고, `안 본 것 n` 또는 `다 답함`을 달고 있다. **저절로 접히지는 않는다** — 마지막 항목에 답하는 순간 손가락 밑에서 묶음이 사라지면 안 된다.
- **공장주 웹**(`owner.js` 점검 기록)도 `이상 없음 n개 · 해당 없음 m개`로 나눠 세고, 펼치면 `… — 해당 없음 (이 공장에 없는 것)`으로 구분해 적는다.
- **안 가져온 것**: 아래 탭 바 다섯 개 · `4.1 / 4.2` 두 자리 번호 · 오른쪽 위 작은 ⓘ · "구역 전체 해당 없음"(안전 점검에서 한꺼번에 넘기는 길은 두지 않는다).
- 동작: `data-act="ans"`(`data-v="ok|na"`) · `data-act="ansBad"`(시트) · `data-act="fold"`(`data-k=출처`). `ansOk`·`reAns`는 없앴다.

**화면 설명 줄을 걷어냈다 (2026-09-18 사용자 지시).** 지운 것: 홈의 "체크리스트 받아 둠" 배지 · 오늘 일정의 "가기 전에 볼 것 보기" · 내 할 일·점검 시작·내 점검 기록의 큰 제목 밑 설명 · 방문 전 "첫 점검이에요…" · 사진 화면의 단계 안내 · 항목 고르기의 "① → ② → ③" 안내와 AI 권유 설명 · 시트의 중복 설명 · 답한 항목 수 겹치는 줄. **남긴 것**(뜻이 있어서): "고르지 않아도 전부 점검" · "사진 속 것만 봐요 · 틀릴 수 있어요" · "사진에서 찾은 것 없음 — 위험이 없다는 뜻은 아니에요" · "전파 없음 / 전파가 잡히면 저절로 올라가요" · "내고 나면 고칠 수 없어요".

## 지킴이 앱을 기존 웹 방식에 맞춤 (2026-09-22)

기존 화성 산업안전지킴이 웹의 방식을 따르기로 하면서(`../260921_기존시스템_분석.md`) 지킴이 앱을 고쳤다.

- **조와 권역** — 김지킴은 **전기 1조**(조장 이조장 + 조원 김지킴·박지킴·최지킴)이고, 조가 **동탄·향남·봉담·우정** 권역을 맡는다(`seed.js`의 `TEAM`). 홈과 내 할 일에 조·권역이 나오고, 내 할 일은 **권역으로 걸러 본다**. "담당 공장" 칸은 "우리 권역"이 되었다(아직 준비 중).
- **기본 체크리스트 34문항 5영역, 판 `26VER01`**(`CHECKLIST`) — 01 산업안전 일반 4 · 02 소방안전 3 · 03 전기안전 4 · 04 화학안전 3(여기까지 공통 14) · 05 유해위험기구·시설 20(설비별). 영역과 문항 수는 기존 웹에서 확인한 것이고 **문항 글은 예시**다. 점검 목록은 영역마다 묶이고 `공통`/`설비별` 꼬리표가 붙는다. 고르기 화면은 영역 다섯 줄로 요약한다. 업종별 판(`BASE_ITEMS`)은 옛 점검 기록에만 남았다.
- **운영자 제출 검사** — 점검을 내면 **검사 대기**가 되고, 운영자가 **승인**하면 문제 항목이 공장주에게 개선 요청으로 가고, **반려**하면 지킴이 내 할 일 맨 위에 "반려됨"으로 돌아온다. **고쳐서 다시 내기**는 답을 그대로 둔 채 목록을 다시 열고, 위에 반려 사유를 띄운다. 다시 내면 같은 기록에 덮고 반려 이력(`backs`)은 남긴다. 반려 사유는 예시 문구다(`가설` — 기존 웹에 사유 칸이 있는지 모른다).
- **공장주·운영자는 승인된 점검만 센다** — `APPROVED()`(`common.js`)로 공장주 기록·고칠 것, 재점검 목록, 운영자 현황 집계를 거른다. 상태가 없는 옛 기록은 승인된 것으로 읽는다(그래서 `SEED.v`를 올리지 않았고 켜 둔 서버의 데이터가 그대로 이어진다).
- **점검 결과 종류** — 다 답하면 `점검완료 · 재점검 · 패트롤 · 기타` 중 하나를 고른다(기본 점검완료, `가설`). 결과를 내는 자리의 안내는 "운영자가 검사해요 · 반려되면 고쳐서 다시 · 승인되면 개선 요청"으로 바뀌었다(옛 "공장주와 운영자가 바로 봐요"는 틀린 말이 되어 뺐다).
- **내 점검 기록** — 줄마다 `검사 대기 / 승인 / 반려됨` 표시, 결과 종류·판 번호. 반려된 것에는 사유와 "고쳐서 다시 내기".
- **주간 보고(G9, 새 화면)** — 기존 웹 "주간점검"의 칸(점검조·작성자·점검 기업 수·결과별 수)을 따른다. 이번 주 실적은 **점검 기록에서 저절로 센다** — 지킴이는 특이 사항만 적고(안 써도 됨) 낸다. 우리 재점검(고쳤나 다시 보러 간 것)은 기존 칸의 "재점검"으로 센다(`가설`).
- **재점검(G6)은 아직 검사를 거치지 않는다** — 내면 바로 반영된다(`가설`). 기존 웹의 "재점검"이 "고쳤나 다시 본 점검"인지 "다시 와야 하는 점검"인지 모르기 때문이다. **이름이 겹친다** — 뜻을 확인하면 둘 중 하나의 이름을 바꿔야 한다.
- 상태 칩 이름은 `.stt.s-wait/.s-ok/.s-back`이다 — `.back`이 이미 뒤로 가기 단추 규칙이라 그대로 쓰면 칩이 부푼다.

## 임시 DB와 로그인 (2026-09-17)

`server.py`(표준 라이브러리만)가 파일을 내주고 `data/proto.db`(SQLite)에 둔다.

| 표 | 담는 것 |
|---|---|
| `accounts` | 공장주·운영자 계정 (비밀번호는 salt + PBKDF2) |
| `sessions` | 로그인 쿠키 |
| `state` | 화면 데이터 한 덩어리(JSON) + 버전 번호 |

시험용 계정 — 비밀번호 모두 `1234`

| 아이디 | 역할 | 로그인하면 |
|---|---|---|
| `daesung` | 공장주 · 대성정밀(박대표) | 공장주 웹 — 대성정밀만 보임 (센서 경보 있음) |
| `hanbit` | 공장주 · 한빛화학(최대표) | 공장주 웹 — 한빛화학만 보임 |
| `admin` | 운영자 · 화성시 운영센터(이운영) | 운영자 웹 — 현황판 · 공장 목록 · 공장 한 곳 |

- **여러 기기가 같은 데이터를 본다.** 각 화면이 1초마다 서버에서 새 데이터를 받는다. 두 기기가 동시에 바꾸면 늦은 쪽이 최신을 받아 다시 적용한다.
- **근로자는 초대로 들어온다** (설계대로). 시험용 초대 코드 — `DS-KIM`(김근로·한국어) · `DS-NGUYEN`(Nguyen Van A·베트남어) · `DS-USED`(이미 쓴 초대) · `DS-OLD`(기간 지난 초대). 열린 초대는 여러 번 시험하도록 써도 닫지 않는다(시험 편의). 링크로 열기: `worker.html#/join/DS-KIM`. 앱과 웹은 로그인 쿠키를 따로 쓴다.
- 지킴이 앱은 아직 로그인 없이 연다.
- 근로자 앱 화면 말은 `i18n.js`에 한국어·베트남어·영어로 있다. 베트남어·영어는 **초벌 번역이라 원어민 검수가 필요**하다. 경보 문구는 미리 번역한 문구, 공지·의견 본문만 "AI 번역" 표시가 붙는다.
- 공장주 의견 화면이 생겼으므로 조작판의 "최근 의견 · 대표님 읽음/답/해결함"은 빠른 시연용으로만 남겨 둔다.
- 공장주가 만든 초대는 한 번 쓰면 닫힌다. 새 공지·답의 외국어 번역은 "(AI 번역 시연 · 언어) 원문" 꼴의 가짜다 — 실제 번역은 붙이지 않았다.
- **아이디·비밀번호 로그인은 시험 편의로만 쓴다** (2026-09-17). 설계 결정은 그대로 "공장주는 휴대폰 번호 인증"이다.
- 이 시제품은 UI/UX 연구 도구다. 화면·흐름에 공을 들이고, 서버·DB·인증은 적당히 돌아갈 만큼만 만든다.
