# 시제품 원칙 점검 (2026-09-17)

폰에서 눌러 보는 시제품(`시제품/`)을 4단계 원칙 4묶음의 **전체 항목**으로 다시 훑은 결과다. 앞선 점검(`4단계_시안/260917_원칙전체점검.md`)은 흑백 스케치가 대상이었다. 이번에는 실제로 돌아가는 화면이라 눌러 보고, 글자 대비·누를 곳 크기 같은 값을 직접 쟀다.

## 어떻게 했나

- 켜 둔 시제품의 데이터를 건드리지 않도록 복사본을 따로 띄워, 시험 세 벌(`_시험/flow.js` · `worker_flow.js` · `cross_flow.js`)로 화면 107장을 찍었다.
- 원칙 묶음마다 점검자를 따로 두고 동시에 훑었다. 점검자는 코드와 캡처를 대조했고, 캡처에 없는 상황(경보 네 건 동시, 완료 화면에 머무는 동안 새 경보, 끊김과 경보 겹침, 2시간 방치, 점검 다시 시작 등)은 각자 복사본을 띄워 직접 눌러 봤다. 시제품 파일은 고치지 않았다.
  - ① 닐슨 10원칙 — 모든 화면
  - ② ISA-101(화면) · ISA-18.2(경보) — 경보·현황 화면
  - ③ Microsoft 사람-AI 18원칙 — AI 제안, 자동 번역, 이상 판정, 작업 예정 알리기, 고장 판단
  - ④ KWCAG 2.2 + 현장 조건 — 모든 화면. 390·320·1280 폭에서 계산값을 쟀다
- 이미 정한 결정(경보 화면에 닫기 없음, 근로자는 센서 값을 안 봄, 기록은 못 고침, 2×2 큰 칸, 경보 빨강·큰 버튼 등)은 뒤집지 않았다. 시험 편의(아이디·비밀번호 로그인, 가짜 번역·AI, 푸시 없음)와 아직 안 만든 메뉴는 지적하지 않았다.
- 여러 묶음이 같은 곳을 짚은 것은 하나로 합치고 출처를 모두 적었다. 크다로 올린 것은 코드로 확인했고, 대부분 직접 눌러서 다시 확인했다.
- 출처 표시: `닐`=닐슨 · `경`=ISA · `AI`=사람-AI · `접`=KWCAG·현장
- 크기: **크다** = 할 일을 못 하거나, 경보를 놓치거나, 틀린 기록이 굳는다 / 작다 = 불편하지만 할 수 있다
- 근거의 파일:행은 2026-09-17 시제품 기준이다.

합치면 **크다 20건**, 작다 약 45건이다. 크게 세 가지가 드러났다.

1. **"이상 없음"을 너무 쉽게 말한다.** 센서가 수리 중이거나 값이 끊겼는데도 공장주·운영자 화면, 근로자 홈이 "이상 없음"이라고 한다. 수리로 닫힌 경보에는 "센서 정상"이라고 뜬다. 스케치에서 정한 "모르는 것을 괜찮다고 보여 주지 않는다"가 시제품으로 옮기면서 일부 빠졌다.
2. **작업 예정 알리기가 화면 말보다 세게 작동한다.** 글만 쓰면 그 센서의 경보가 통째로 꺼지고, 고쳐 써도 앞 글이 남으며, 꺼진 경보는 아무 화면에도 남지 않는다.
3. **키보드·화면 읽기·연한 글자.** 흑백 스케치로는 볼 수 없던 구현 문제다. 연한 회색 글자의 대비가 3.06:1이고, 웹의 표 줄과 고르기 칸은 키보드로 누를 수 없다.
